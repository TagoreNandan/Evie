# Plan 02-02: Briefing Delivery Triggers & FastAPI Endpoints (`main.py`)

## Goal
Implement the FastAPI server (`main.py`) providing the three briefing delivery endpoints: real-time GitHub webhook (`POST /webhooks/github`), wake-triggered morning report (`GET /briefing/wake`), and on-demand briefing query (`GET /briefing/on-demand`) (`BRIEF-02`, `BRIEF-03`, `BRIEF-04`).

## User Review Required
> [!IMPORTANT]
> - All three endpoints delegate directly to `services.briefing:generate_briefing()`. No briefing logic may be duplicated inside endpoint functions.
> - Webhook HMAC SHA-256 signature verification is mandatory whenever a secret is set in OS keyring. Invalid or missing signatures MUST be rejected with HTTP 401 before any database write or briefing generation.
> - Webhook processing is idempotent using `X-GitHub-Delivery` header. Replayed deliveries must be ignored.
> - FastAPI binds exclusively to `127.0.0.1` (localhost) by default. Remote exposure requires an explicitly configured secure tunnel with secret verification.

## Proposed Changes

### Component 1: FastAPI Web Application & Local Server

#### [NEW] [`main.py`](file:///Users/somespecies/Desktop/Evie/main.py)
- Create FastAPI application instance `app`.
- Default server runner (`uvicorn.run`) binds exclusively to `127.0.0.1:8000` (localhost only; never `0.0.0.0`).
- Add startup event handler to initialize SQLite database tables (`github_events`, `calendar_actions`, `secret_findings`, `breach_checks`, `exposure_findings`, `twofa_audit`). Ensure `github_events` includes `delivery_id TEXT UNIQUE`.

- Implement `POST /webhooks/github`:
  - **Mandatory Signature Verification**:
    - Retrieve `github_webhook_secret` via `keyring_utils.get_credential("evie_assistant", "github_webhook_secret")`.
    - If secret exists: extract `X-Hub-Signature-256` header. If missing or invalid (computed using `hmac.new(..., digestmod=hashlib.sha256)` and constant-time comparison `hmac.compare_digest`), return HTTP 401 `{"detail": "UNAUTHORIZED_WEBHOOK"}` **before** any database operation.
    - If no secret is configured in OS keyring: log a local dev warning and accept webhooks strictly when local dev mode is active.
  - **Idempotency Check (`X-GitHub-Delivery`)**:
    - Extract `delivery_id` from `X-GitHub-Delivery` header.
    - Check if `delivery_id` already exists in `github_events` table. If present, return HTTP 200 `{"status": "already_processed", "delivery_id": delivery_id}` without duplicate database insertion or briefing invocation.
  - **Data Minimization & Storage**:
    - Extract minimal schema fields (`repo_name`, `event_type`, `actor`, `summary`). **Do not store raw webhook JSON body or output raw payload in logs/errors.**
    - Insert event record into `github_events` table (`delivery_id`, `notified_realtime = 1`, `included_in_briefing = 0`).
    - Invoke `generate_briefing(db_path, trigger="webhook", repo_name=repo_name)`.
    - Return HTTP 200 JSON with event status and notification summary.

- Implement `GET /briefing/wake`:
  - Simple GET trigger endpoint with no uncontrolled path/credential parameters.
  - Delegate directly to `generate_briefing(db_path, trigger="wake")`.
  - Return HTTP 200 OK JSON response. Safe error handling: catch internal exceptions and return stable HTTP 500 `{"detail": "BRIEFING_GENERATION_FAILED"}` without raw tracebacks or secret leaks.

- Implement `GET /briefing/on-demand` (and alias `/report/full`):
  - Simple GET trigger endpoint with no uncontrolled path/credential parameters.
  - Delegate directly to `generate_briefing(db_path, trigger="on_demand")`.
  - Return HTTP 200 OK JSON response. Safe error handling with stable status codes.
