# Plan 02-01: Shared Briefing Aggregator Engine (`services/briefing.py`)

## Goal
Implement the central briefing aggregation engine in `services/briefing.py` that consolidates overnight GitHub activity, today's calendar events, active security findings, and general highlights into a single structured report (`BRIEF-01`).

## User Review Required
> [!IMPORTANT]
> - All briefing triggers (webhook, wake, on-demand) call this single aggregation function (`services/briefing.py:generate_briefing`). Logic must not be duplicated across triggers.
> - If an external data source (e.g. Google Calendar API) is unavailable or fails, `generate_briefing` surfaces the error safely in the section status (`status="unavailable"`, stable `error_code`) and proceeds with the remaining sections. It must never fail silently or generate fake data.
> - Raw secrets, tokens, credentials, or PII must never be written to briefing outputs or exception logs.

## Proposed Changes

### Component 1: SQLite Schema & Service Module

#### [NEW] [`services/briefing.py`](file:///Users/somespecies/Desktop/Evie/services/briefing.py)
- Create `services/` package directory and `services/__init__.py`.
- Implement `init_github_events_table(db_path: str)` to ensure `github_events` SQLite table exists per `04_Backend_Schema.md`.
- Implement Calendar Client Helper Boundary `fetch_today_calendar_events(oauth_token: str | None = None) -> list[dict]`:
  - Small, isolated helper function fetching today's events from Google Calendar REST API (`https://www.googleapis.com/calendar/v3/calendars/primary/events`).
  - Allows `generate_briefing` aggregation logic to be unit-tested cleanly by mocking `fetch_today_calendar_events` without real network calls or large frameworks.
- Implement `generate_briefing(db_path: str = "evie.db", trigger: str = "wake", repo_name: str | None = None) -> dict`:
  - **Deterministic GitHub Deduplication**:
    - Queries `github_events` table strictly where `included_in_briefing = 0` (optionally filtered by `repo_name` if supplied).
    - Avoids vague "recent" logic that could re-announce already processed events.
    - Atomically updates `included_in_briefing = 1` for exactly the selected events included in the report payload.
  - **Safe Calendar Section & Error Handling**:
    - Retrieves OAuth token via `keyring_utils.get_credential("evie_assistant", "google_calendar_oauth")`.
    - Invokes `fetch_today_calendar_events()`.
    - If token is missing or an exception occurs, catches the exception and records safe structured status:
      `calendar_today: {"status": "unavailable", "error_code": "CALENDAR_FETCH_FAILED", "category": "API_ERROR"}` (or `"CREDENTIAL_MISSING"`).
    - Append safe error record to `partial_failures`. **Never place raw `str(e)` or exception tracebacks that could contain credentials/tokens into returned briefing output.** Any detailed internal logging must pass through `redaction.redact_text()`.
  - **Security Findings Section (Phase 1 Schema Alignment)**:
    - Queries Phase 1 SQLite tables: `secret_findings`, `breach_checks`, `exposure_findings`, and `twofa_audit`.
    - Summarizes open finding counts and safe metadata (`redacted_preview`, `repo_name`, `exposure_type`, `status`).
    - **Raw secret values are strictly prohibited** from entering briefing outputs, logs, or database entries.
  - **Output**: Returns structured dictionary containing `timestamp`, `trigger`, `summary`, `sections` (`github_activity`, `calendar_today`, `security_findings`), and `partial_failures`.
