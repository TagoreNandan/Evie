# Plan 04-02: Remediation Guidance & Dependabot Watcher (`remediation.py` & `integrations/dependency_watch.py`)

## Goal
Implement step-by-step remediation guide generation (`remediation.py`) (`SCORE-02`) and GitHub Dependabot vulnerability alert monitoring (`integrations/dependency_watch.py`) (`SCORE-03`).

## User Review Required
> [!IMPORTANT]
> - Remediation guides provide instructional steps ONLY. No automated destructive remediation is executed automatically.
> - Dependabot integration uses GitHub API read-only scope (`security_events`).

## Proposed Changes

### Component 1: Remediation Guide Generator

#### [NEW] [`remediation.py`](file:///Users/somespecies/Desktop/Evie/remediation.py)
- Create module docstring referencing `SCORE-02` and Section 8 of `06_Acceptance_Criteria.md`.
- Implement `get_remediation_guide(finding_type: str, finding_id: int, db_path: str = "evie.db") -> dict`:
  - Fetch target finding from corresponding SQLite table (`secret_findings`, `breach_checks`, `exposure_findings`, `twofa_audit`, `dependency_alerts`).
  - If finding not found, raise `ValueError("Finding not found")`.
  - Construct custom, step-by-step resolution guide matching the finding details:
    - Secret findings: steps for AWS/PAT/key revocation, environment variable migration, git history cleanup.
    - Breach checks: steps for password change, 2FA activation, email monitoring.
    - Public exposures: steps for Drive/Calendar sharing permission adjustment (restricted access).
    - 2FA audit: steps for enabling 2FA on Google/GitHub accounts.
    - Dependabot alerts: steps for upgrading vulnerable dependencies (`pip install --upgrade`, `package.json` patch).
  - Return `{"finding_type": finding_type, "finding_id": finding_id, "title": title, "severity": severity, "steps": list[str]}`.

### Component 2: Dependabot Alert Watcher

#### [NEW] [`integrations/dependency_watch.py`](file:///Users/somespecies/Desktop/Evie/integrations/dependency_watch.py)
- Implement `init_dependency_alerts_table(db_path: str = "evie.db") -> None`:
  Create `dependency_alerts` SQLite table per `04_Backend_Schema.md`.
- Implement `fetch_dependabot_alerts(repo_name: str, github_pat: str | None = None, db_path: str = "evie.db") -> list[dict]`:
  - Retrieve GitHub PAT from OS Keyring (`keyring_utils.get_credential("evie_assistant", "github_pat")`) if `github_pat` not supplied.
  - Call GitHub REST API `https://api.github.com/repos/{repo_name}/dependabot/alerts` using `httpx.Client`.
  - Parse open alerts (`package.name`, `security_advisory.severity`, `html_url`).
  - Store open alerts in `dependency_alerts` SQLite table (`repo_name`, `package_name`, `severity`, `advisory_url`, `status = 'open'`).
  - Return list of stored dependency alert dicts.
