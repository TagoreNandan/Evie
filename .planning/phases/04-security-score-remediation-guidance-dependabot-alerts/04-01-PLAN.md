# Plan 04-01: Security Health Score Aggregator (`security_score.py`)

## Goal
Implement `security_score.py` providing dynamic 0–100 Security Health Score calculation, breakdown breakdown logging in `security_score_history`, and `GET /score` endpoint (`SCORE-01`).

## User Review Required
> [!IMPORTANT]
> - Score calculation is deterministic: baseline 100 with fixed penalty deductions per open finding type, clamped to `[0, 100]`.
> - Score breakdown and computed timestamp must be persisted in SQLite `security_score_history` table.

## Proposed Changes

### Component 1: Score Aggregator Module

#### [NEW] [`security_score.py`](file:///Users/somespecies/Desktop/Evie/security_score.py)
- Create module docstring referencing Section 8 of `06_Acceptance_Criteria.md` and `SCORE-01`.
- Implement `init_score_history_table(db_path: str = "evie.db") -> None`:
  Create `security_score_history` SQLite table per `04_Backend_Schema.md`.
- Implement `compute_security_score(db_path: str = "evie.db", log_history: bool = True) -> dict`:
  - Baseline score = 100.
  - Deduct `-15` per open secret finding in `secret_findings`.
  - Deduct `-10` per unacknowledged breach check in `breach_checks`.
  - Deduct `-10` per open public exposure in `exposure_findings`.
  - Deduct `-15` per unenabled provider in `twofa_audit`.
  - Deduct `-10` per critical/high severity alert in `dependency_alerts`.
  - Clamp final score between `0` and `100`.
  - Determine trend (`"improving"`, `"declining"`, `"stable"`) by comparing against latest score in `security_score_history`.
  - Record score entry into `security_score_history` table (`score`, `breakdown` JSON string, `computed_at`).
  - Return `{"score": score, "trend": trend, "breakdown": breakdown_dict, "computed_at": timestamp}`.

### Component 2: FastAPI Route Integration
