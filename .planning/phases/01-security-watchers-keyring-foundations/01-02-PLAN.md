# Plan 01-02: GitHub Secret Scanner Engine

## Objective

Build `integrations/github_watch.py` to scan git commit diffs for leaked secrets using regex patterns and Shannon entropy analysis. Ensure detected secrets are automatically redacted before returning or storing findings.

## Tasks

### Task 1: Secret Detection Core Engine (`integrations/github_watch.py`)
- **Type**: tracer
- **Description**: Implement `SecretScanner` class with pattern regexes for standard secret formats (GitHub PATs/tokens `ghp_...`/`github_pat_...`, OpenAI keys `sk-...`, Anthropic API keys `sk-ant-...`, AWS access keys `AKIA...`, and Slack webhooks). Add Shannon entropy calculation algorithm ($H(X) > 4.5$ on extracted candidate secret-like tokens $>20$ chars, evaluated on discrete word/alphanumeric tokens rather than arbitrary source-code substrings to minimize false positives). Include `scan_diff(diff_text: str) -> list[dict]` returning findings with `secret_type`, `redacted_value`, `line_number`, and `entropy_score`. Raw unredacted secret values are strictly prohibited from appearing in returned findings, log messages, exception tracebacks, diff fragments, test failure output, or stored data — raw strings may exist only transiently inside the scanner during evaluation.
- **Files**:
  - `integrations/github_watch.py`
  - `tests/test_secret_scanner.py`
- **Threat Model**:
  - *Risk*: Scanner logs or returns raw unredacted secret in finding dict, diff fragment, or exception output.
  - *Mitigation*: The `SecretScanner` class must pass all candidate matches through `redact_secret()` before constructing finding objects. Raw values must never be formatted into output or exception messages.
- **Automated Verification**: `pytest tests/test_secret_scanner.py`

### Task 2: Git Commit & PyGithub Integration
- **Type**: task
- **Description**: Add `scan_local_commit(repo_path: str, commit_sha: str) -> list[dict]` and `scan_github_repository_commits(repo_name: str, token_key: str = "github_token") -> list[dict]`. Define `scan_local_commit` explicitly as scanning the diff between `commit_sha` and its first parent (e.g. `["git", "diff", f"{commit_sha}^!", ...]`). All local git subprocess calls MUST use list argument arrays with `shell=False` and checked return codes (`check=True` or explicit status check); no string interpolation into shell command strings. Require `scan_github_repository_commits` to retrieve the GitHub token via `keyring_utils.get_credential("evie_assistant", token_key)` rather than requiring callers to manage or pass plaintext credentials. Unit tests must mock `keyring_utils` and `PyGithub` interactions.
- **Files**:
  - `integrations/github_watch.py`
  - `tests/test_secret_scanner.py`
- **Threat Model**:
  - *Risk*: Shell injection via repo paths/commit SHAs, or caller exposure of plaintext tokens.
  - *Mitigation*: Enforce `shell=False` list arrays for subprocess calls and OS Keyring lookup for API tokens.
- **Automated Verification**: `pytest tests/test_secret_scanner.py`
