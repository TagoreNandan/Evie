# Plan 01-04: Drive & Calendar Public Exposure Auditor

## Objective

Build `integrations/exposure_watch.py` to audit Google Drive file permissions and Google Calendar ACL resource permissions for unintended public access (`anyone`) or external domain sharing outside configured trusted domains.

## Tasks

### Task 1: Drive File Sharing Auditor (`integrations/exposure_watch.py`)
- **Type**: tracer
- **Description**: Build `DriveExposureAuditor` class with `audit_drive_permissions(credentials, trusted_domains: set[str] | None = None) -> list[dict]`.
  - *Trusted Domain Policy*: Supply trusted domains from Evie configuration (`config.py` or `trusted_domains` argument). Never hard-code company or domain values. Flag a domain permission as `external_domain` only when its domain is outside the configured trusted-domain set.
  - *Exposure Classification*: Findings MUST contain an explicit `exposure_type` set to `"public"` (when permission `type` is `"anyone"`) or `"external_domain"` (when `type` is `"domain"` or `"user"` with an external domain). Preserve permission `role` (`reader`, `commenter`, `writer`, `owner`).
  - *Pagination & Error Handling*: Process every `files.list` page using `nextPageToken`. Explicitly raise API exceptions on failure — never return partial results as if the audit were complete.
  - *Data & PII Minimization*: Query ONLY necessary metadata fields (`fields="nextPageToken, files(id, name, mimeType, permissions(id, type, role, domain, emailAddress))"`). Do NOT download or inspect document/file contents. Do not log full external user email addresses (redact email local-parts).
  - *OAuth Scope*: Enforce least-privilege OAuth scope `https://www.googleapis.com/auth/drive.metadata.readonly`.
  - *Testing*: Unit tests in `tests/test_exposure_watch.py` must mock Google API discovery client responses and cover multi-page pagination results and pagination failure exceptions.
- **Files**:
  - `integrations/exposure_watch.py`
  - `tests/test_exposure_watch.py`
- **Threat Model**:
  - *Risk*: Silent truncation of audit results from failed pagination, or PII leakage / over-scoped OAuth access.
  - *Mitigation*: Enforce full pagination loops with error propagation, apply least-privilege scopes, and sanitize PII in findings.
- **Automated Verification**: `pytest tests/test_exposure_watch.py`

### Task 2: Calendar ACL Sharing Auditor (`integrations/exposure_watch.py`)
- **Type**: task
- **Description**: Add `CalendarExposureAuditor` class with `audit_calendar_acls(credentials, trusted_domains: set[str] | None = None) -> list[dict]`.
  - *Calendar Scope*: Audit Google Calendar ACL endpoints (`calendarList().list()` and `acl().list()`) for calendar resources. Do NOT retrieve event titles, descriptions, attendees, or event bodies. Findings identify affected calendar resource ID and summary only.
  - *Exposure Classification*: Set `exposure_type` to `"public"` (when ACL `scope.type` is `"default"` or `"anyone"`) or `"external_domain"` (when `scope.type` is `"domain"` or `"user"` outside configured trusted domains). Preserve ACL `role` (`freeBusyReader`, `reader`, `writer`, `owner`).
  - *PII Minimization*: Omit or redact individual external user email addresses in logs and returned findings.
  - *OAuth Scope*: Enforce least-privilege OAuth scope `https://www.googleapis.com/auth/calendar.acls.readonly` or `calendar.readonly`.
  - *Testing*: Unit tests in `tests/test_exposure_watch.py` must mock Google Calendar API client responses.
- **Files**:
  - `integrations/exposure_watch.py`
  - `tests/test_exposure_watch.py`
- **Threat Model**:
  - *Risk*: Over-retrieval of private calendar event contents or over-scoped calendar permissions.
  - *Mitigation*: Restrict API queries strictly to Calendar ACL endpoints and use read-only ACL scopes.
- **Automated Verification**: `pytest tests/test_exposure_watch.py`

## Verification Strategy
