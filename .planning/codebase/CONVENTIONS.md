# Coding Conventions & System Guardrails

**Analysis Date:** 2026-09-19

## Overview
All development in Evie must strictly adhere to the engineering standards and hard constraints defined in `AGENTS.md` and `docs/02_TRD.md`.

---

## Hard Architectural Guardrails

### 1. Secret Protection & Zero-Leakage Policy
- **Redaction Required**: Detected API keys, credentials, or tokens must be redacted immediately (e.g. `AKIA****...**34`, showing first/last 2 characters only).
- **Zero-Plaintext Ingestion**: Secret values MUST NEVER be printed to terminal stdout/stderr, written to log files, returned in API payloads, or stored in SQLite database rows.
- **Keyring Storage**: API tokens and OAuth refresh tokens must be kept in the OS keyring (`keyring` library) or a Fernet-encrypted local file. Never in `.env` files committed to git or in SQLite tables.

### 2. Two-Phase Calendar Write Safety
- Direct calendar mutations are prohibited.
- Calendar writes follow an explicit two-phase protocol:
  1. `POST /calendar/propose`: Generates proposal and returns confirmation prompt to user.
  2. `POST /calendar/confirm`: Executes Google Calendar mutation upon explicit user approval.

### 3. Unified Reporting Function
- Aggregation logic for daily briefings MUST NOT be duplicated across real-time webhooks, wake-triggered greetings, and on-demand queries.
- All three delivery mechanisms must invoke a single shared function (`get_full_report()` in orchestrator).

### 4. Honest API Error Handling
- Never fabricate mock or placeholder data when external API calls fail (e.g. HIBP, GitHub, Google API downtime). Fail transparently and report the error state to the user.

### 5. Evidence-Based DRS Framing
- Answers generated by the Decision/Research Support System (DRS) must include cited sources and explicitly frame advice as evidence-based support rather than authoritative verdicts.

---

## Python Coding Style

- **Python Version**: Python 3.11+.
- **Module Header**: Every module must begin with a docstring explaining its responsibilities and referencing the exact section of `02_TRD.md` it implements.
- **Async Standard**: Use FastAPI `async def` handlers and non-blocking HTTP clients (`httpx`) for external API interaction.
- **Configuration**: System parameters loaded from a centralized `config.py` module.
